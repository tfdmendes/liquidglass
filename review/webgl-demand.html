Measure to count work

Counters are real drawArrays and texImage2D calls. Capture/Compare explicitly renders once; measure samples exclude those captures.
What changes
  • Immutable ImageBitmap and paused video sleep between updates. Moving a lens reuses the uploaded source; reshaping updates only its lens map.
  • Canvas and HTMLImageElement stay continuous. An animated SVG can change WebGL pixels without a load event; a URL extension is not a safe classifier. Use the existing ImageBitmap source type for a static snapshot.
  • Video uses requestVideoFrameCallback when available, with an animation-frame fallback. Play/pause, seeking, loading, replacement, visibility, size and DPR changes wake the renderer.
  • Stop retains the last displayed output. Explicit render() refreshes pixels while stopped. Destroy releases callbacks, observers and GPU resources.
Validation, assumptions and limits

Recorded: 12 runs in Chrome 156 / Blink and Firefox 157 / Gecko, plus 2 native WKWebView runs (WebKit 22625.1.29.11.28). All readback samples matched within each engine: 2,288 assertions, plus 36 focused video assertions after cleanup. Run the checks for the browser displaying this page.

Counts measure operations, not CPU percentage. Concurrent work can affect elapsed samples. Playing videos decode independently; pause at 0.5 s for an exact-time comparison. Readback is immediate after drawing; the browser may clear its WebGL buffer after compositing. Visibility handling used an overridden document.hidden getter and a real visibilitychange event; native background-tab suspension was not demonstrated. Dynamic DPR used a resize signal because DevTools does not emit the normal change events; initial DPR settings were real browser emulation. No physical iPhone or stock Firefox application was tested.

Browser callbacks follow the video-frame callback draft; WebGL resources are recreated after context restoration.
